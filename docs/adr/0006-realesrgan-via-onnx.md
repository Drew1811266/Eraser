# ADR-0006 · 超分：把 Real-ESRGAN 编译成 ONNX，而不是复刻参考实现的 torch 运行时

- **状态**：**已采纳**（2026-11-21）
- **日期**：2026-11-21
- **关联**：ADR-0001（不引入 torch）、`src/core/realesrgan_runtime.py`（被替代对象）

---

## 背景

参考实现的超分不是"一个模型"，是一整套独立运行时：

1. 找到一个 **Python 3.12** 解释器；
2. 为它创建隔离 venv；
3. `pip install` Real-ESRGAN 的推理依赖（含 **torch**）；
4. 起一个 worker 子进程，通过 `selectors` 桥接进度、取消、超时。

它还有 1644 行的 `upscale_processor.py` 在管 tile、模式、目标预设。

这套东西在 mac 上能跑，但搬到 Windows 会同时违背三条已锁定的决策：
ADR-0001 明确"不引入 torch"，安装包体积会从 601MB 涨到 3GB 以上，
而且"在用户机器上 pip install"这件事本身就是不稳定源（网络、编译、磁盘）。

同时它也不是"保真"的必需品：Real-ESRGAN 的生成器就是一个 **23 个 RRDB 块的纯卷积网络**，
没有控制流、没有自定义算子，是 ONNX 最擅长的那类图。

---

## 评估

| 方案 | 体积 | 可靠性 | 工作量 |
|---|---|---|---|
| 复刻 venv + torch worker | +2GB 以上 | 差：依赖用户机器上的 Python 3.12 与网络 | 高（1644 行 + 运行时管理） |
| **转成 ONNX，复用已有 onnxruntime**（选定） | +64MB 模型 | 好：与 LaMa 同一条推理链路 | 中：一次转换 + 分块推理 |
| 不做超分 | 0 | — | 0 |

---

## 决策

1. 用 `packaging/convert-esrgan.py` 在**构建期**把官方 `RealESRGAN_x4plus.pth` 转成 ONNX（67MB）；
   torch 只是构建依赖，**不进引擎、不进安装包**。
2. 架构按 checkpoint 的真实键名实现（`conv_first` / `body.N.rdbM.convK` / `conv_body` /
   `conv_up1` / `conv_up2` / `conv_hr` / `conv_last`），`load_state_dict(strict=True)` 通过即证明结构一致。
3. 转换脚本自带校验：同一输入下 ONNX 与 PyTorch 的最大绝对误差必须 < 1e-3（实测 1.1e-06），
   并且对两个不同尺寸都要成立，确保空间维度是动态的。
4. 运行时按 256px 分块、24px 重叠，裁掉重叠区后拼接：不加混合也能做到无缝，
   因为重叠区只是给卷积提供上下文。
5. 2× 由 4× 结果 lanczos 下采样得到——比让模型假装支持 2× 更清晰。
6. 音频先出无声视频、再二次无损封装音轨；音频封装失败也仍然留下可用的无声结果。

---

## 验收

`scripts/e2e-upscale.py` 证明了三件"不会抛异常"的失败模式都没有发生：

| 检查 | 结果 |
|---|---|
| 输出分辨率是请求倍数 | 640×360 → 2560×1440 ✅ |
| 帧数不变 | 12 → 12 ✅ |
| 内容没跑偏（缩回原尺寸对比） | 平均绝对误差 1.23/255 ✅ |
| 确实比 bicubic 更锐（Laplacian 能量） | 0.4 vs 0.2 ✅ |

单测另有 7 项覆盖分块拼接：用"最近邻放大"的假 session 验证
**分块结果必须逐像素等于整图一遍**，任何缝或错位都会失败。

---

## 后果

- **正面**：安装包只增加 64MB；超分与去水印共用 provider 选择、取消语义和错误处理；
  在 5090 上 640×360 → 2560×1440 约 0.5s/帧。
- **负面**：
  - ONNX 文件没有上游官方发布，必须自己转换；`scripts/fetch-assets.py` 因此只校验 sha256 并提供转换命令。
  - 参考实现的"目标预设 / 同分辨率增强 / 多模型"没有移植：v1 只有 x4plus 的 2×/4×。
    这些属于参数层能力，等有真实素材反馈后再决定是否补。
- **接口**：只新增 `upscale.start`，任务生命周期复用 `process.status` / `process.cancel`，
  不引入第二套状态机。
